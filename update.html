PageRivet 3.3.0-beta.2

2026.09.01 · Portable ZIP · Beta

A beta update adding custom themes, Jekyll site preview, a dockable workspace, History restore, and diagnostics integration, while improving current-error refresh and preview stability.

Added

  • Added optional diagnostics status reporting for initialization, user wait, app readiness, and MCP state during diagnostics sessions, plus receiving, execution, and reporting in the separate Diagnostics tool.
  • Custom themes can now edit 16 colors covering backgrounds, menus, panels, inputs, text, borders, accents, and states using square or circular palettes and RGB, HSV, or HEX input.
  • Added settings preview, apply and cancel actions, dark and light default restoration, low-contrast warnings, compatible palette persistence, and per-color fallback recovery.
  • Added localized Jekyll site preview for projects with _config.yml, plus automatic discovery, custom-path selection, and version checks for external Jekyll 4.1+ runtimes.
  • Added generation-based temporary workspaces that isolate editor buffers and managed resources from originals, with support for Front Matter, Liquid, layouts, includes, data, Markdown posts, Sass/SCSS, static assets, and pretty permalinks.
  • Added a docking system for preview, editor, project, history, MCP log, and error/debug panels with splits, tabs, floating windows, layout presets, and off-screen recovery.
  • Added History restore and double-click diff/restore, a project-relative folder tree with case-insensitive filtering, and clearer panel accents and surface hierarchy.

Changed

  • Errors/Debug now shows current validation and preview issues instead of accumulated console history and groups duplicates as ×N; the regular console and MCP get_console_log remain available.
  • Validation and preview now rerun after apply, source changes, and external changes, while ordinary typing is never auto-applied or saved.
  • Jekyll output is served through the existing loopback server and NativeWebView; rebuilds debounce source changes for 350 ms, while manual refresh starts the newest generation immediately.
  • Packaging scripts now read the version from Directory.Build.props instead of duplicating hard-coded values.
  • When panel width is limited, header commands and editor search, previous/next match, and go-to-line actions move into an overflow popover.
  • Updated nested split minimums, chained shrinking, drag ghosts that follow the pointer outside windows, full-height side docking, and drop-time candidate reevaluation.
  • Adjusted the Project panel minimum width, workspace margins, and bottom-panel alignment; docking drag now begins only after the pointer moves at least 6 DIP.
  • Reordered top commands and unified language, theme, workspace, undo/redo, Jekyll, and MCP settings in one window while preserving category, scroll, focus, and selected preset after apply.
  • Project search now uses a 140 ms debounce and rebuilds only matching files and their parent folders.

Fixed

  • Cleared stale runtime errors on new preview publication, blocked delayed messages from different runs or document URLs, and strengthened early script-error collection and latest-request checks.
  • Fixed stale layout nodes canceling cross-workspace panel moves and duplicate panel attachment when maximizing a floating preview.
  • Fixed conflicts between chained minimum sizes and default splitters, plus header titles and commands overflowing into narrow neighboring panels.
  • Fixed a NullReferenceException while rebuilding virtualized History rows and tab clicks being mistaken for drags in History, MCP Log, and Errors/Debug.
  • Matched the Claude Desktop connection dialog to the Workbench theme, preserved workspace-catalog errors, and cancel Jekyll runtime checks when Settings closes.

Security

  • The original project is never used as the Jekyll source or destination, and _site or cache folders are not created in it.
  • Jekyll runs with –safe, –disable-disk-cache, JEKYLL_NO_BUNDLER_REQUIRE=true, and a PageRivet safety configuration.
  • Project Gemfiles, bundle exec, user plugins, automatic installation, and network-download paths are not used.
  • Build time, logs, file counts, and input/output sizes are bounded, and the process tree is terminated on cancellation or timeout.
  • Generated-output path escapes and reparse points are blocked, and old temporary output is cleaned only after active HTTP reads finish.

Existing Features Preserved

  • HTML and PageRivet YAML preview, project editing and saving, History, Recovery, resources, external changes, export, and MCP behavior remain unchanged.
  • Generated Jekyll output is not automatically included in existing exports.
  • Missing Ruby/Jekyll or a failed Jekyll build does not block existing features.
  • Existing editor buffers, selection and cursor state, undo/redo, Preview controller, and MCP approval and revision boundaries are preserved.

PageRivet 3.3.0-beta.2

2026.09.01 · Portable ZIP · Beta

사용자 지정 테마, Jekyll 사이트 미리보기, 도킹 작업공간, History 복원과 진단 연동을 확장하고 현재 오류 갱신 및 미리보기 안정성을 개선한 베타 업데이트입니다.

추가

  • 진단 실행 세션에서만 초기화·사용자 대기·본체 준비·MCP 상태를 전달하는 선택적 진단 상태 송신과 별도 Diagnostics의 수신·실행·보고서 흐름을 추가했습니다.
  • 사용자 지정 테마에서 배경·메뉴·패널·입력·글자·테두리·강조·상태 등 16개 색상을 사각형·원형 팔레트와 RGB·HSV·HEX 입력으로 편집할 수 있습니다.
  • 설정창 샘플 미리보기, 적용·취소, 어두운/밝은 기본값 복원, 낮은 텍스트 대비 경고와 사용자 팔레트의 호환 저장·개별 기본값 복구를 추가했습니다.
  • _config.yml 프로젝트를 위한 지역화된 Jekyll 사이트 미리보기와 외부 Jekyll 4.1 이상 4.x 런타임 자동 검색·사용자 경로·버전 검사를 추가했습니다.
  • 편집 버퍼와 관리 리소스를 원본과 분리된 세대별 임시 작업공간에 구성하고 Front Matter, Liquid, layout, include, data, Markdown post, Sass/SCSS, 정적 리소스와 pretty permalink를 지원합니다.
  • 미리보기·편집기·프로젝트·기록·MCP 로그·오류/디버그를 분할, 탭, 독립 창으로 배치하는 도킹 시스템과 사용자 레이아웃 프리셋 및 화면 이탈 복구를 추가했습니다.
  • History 선택 행의 복원 및 더블클릭 상세 비교·복원 창, 프로젝트 상대 경로 폴더 트리와 대소문자 비구분 필터, 패널별 색상 악센트와 표면 계층을 추가했습니다.

변경

  • 오류/디버그는 누적 콘솔 대신 현재 검증·미리보기 오류와 경고를 표시하고 동일 문제를 ×N 횟수로 합칩니다. 일반 콘솔과 MCP get_console_log는 유지합니다.
  • 적용·소스 변경·외부 변경 반영 후 기존 검증과 미리보기를 다시 실행하되 단순 입력은 자동 적용하거나 저장하지 않습니다.
  • Jekyll 결과를 기존 Loopback 서버와 NativeWebView에서 제공하고 소스 적용 후 재빌드는 350ms 동안 연속 요청을 합치며 수동 새로고침은 즉시 최신 세대를 시작합니다.
  • 패키징 스크립트는 Directory.Build.props에서 버전을 읽으며 중복 하드코딩을 제거했습니다.
  • 패널 폭이 부족하면 헤더 명령과 편집기 검색·이전/다음 찾기·줄 이동을 ⋯ 팝오버로 이동합니다.
  • 중첩 분할 최소 크기, 연쇄 축소, 외부 포인터 추적 드래그 고스트, 전체 높이 좌·우 도킹과 드롭 순간 후보 재판정을 적용했습니다.
  • 프로젝트 패널 최소 폭과 작업영역 여백·하단 패널 정렬을 조정하고 패널 헤더는 포인터가 6 DIP 이상 이동한 뒤에만 도킹 드래그를 시작합니다.
  • 상단 명령을 재정렬하고 언어·테마·작업공간·Undo/Redo·Jekyll·MCP 설정을 하나의 설정창에 통합했으며 적용 후 분류·스크롤·포커스·선택 프리셋을 유지합니다.
  • 프로젝트 검색 입력은 140ms debounce로 합치며 검색 결과의 파일과 상위 폴더만 다시 구성합니다.

수정

  • 새 미리보기 발행 시 이전 실행 오류를 비우고 실행 식별자나 문서 주소가 다른 지연 메시지를 차단하며 초기 스크립트 오류 수집과 최신 요청 재검사를 강화했습니다.
  • 내부 패널을 반대편으로 옮길 때 기존 레이아웃 노드가 남아 이동이 무효화되던 문제와 독립 프리뷰 최대화 시 패널 중복 부착 예외를 수정했습니다.
  • 연쇄 최소 크기와 기본 스플리터 충돌, 좁은 인접 패널로 제목과 명령이 침범하는 문제를 수정했습니다.
  • 독립 History 창의 가상화 행 재구성 NullReferenceException과 기록·MCP 로그·오류/디버그 탭 클릭이 드래그로 오인되던 문제를 수정했습니다.
  • Claude Desktop 연결 안내창 테마를 통일하고 작업공간 카탈로그 오류가 일반 프리셋 오류로 치환되지 않도록 했으며 설정창 종료 시 Jekyll 검사를 취소합니다.

보안

  • 원본 프로젝트를 Jekyll source/destination으로 사용하지 않고 _site와 캐시를 원본에 만들지 않습니다.
  • –safe, –disable-disk-cache, JEKYLL_NO_BUNDLER_REQUIRE=true와 PageRivet 안전 config를 강제합니다.
  • 프로젝트 Gemfile 자동 실행, bundle exec, 사용자 플러그인, 자동 설치와 네트워크 다운로드 경로를 포함하지 않습니다.
  • 빌드 시간·로그·파일 수와 입력·출력 크기를 제한하고 취소·시간 초과 시 프로세스 트리를 종료합니다.
  • 생성 결과의 경로 이탈과 재분석 지점을 차단하고 활성 HTTP 읽기가 끝난 뒤 이전 임시 출력을 정리합니다.

기존 기능 보존

  • HTML 및 PageRivet YAML 미리보기, 프로젝트 편집·저장, History, Recovery, 리소스, 외부 변경, 내보내기와 MCP 동작을 유지합니다.
  • Jekyll 생성 결과는 기존 내보내기에 자동 포함하지 않습니다.
  • Ruby/Jekyll 부재와 Jekyll 빌드 실패는 기존 기능 사용을 차단하지 않습니다.
  • 기존 편집 버퍼, 선택·커서, Undo/Redo, Preview 컨트롤러와 MCP 승인·Revision 경계를 유지합니다.

PageRivet 3.3.0-beta.1

2026.08.27 · Portable ZIP · Beta

The first beta release completing the Avalonia 12.1 UI migration, PageRivet YAML page support, and a shared cross-platform architecture. The Windows x64 release candidate passed automated validation, while real-environment validation remains for macOS and Linux.

Added

  • Added an Avalonia 12.1 cross-platform desktop UI connected to the existing create, open, save, and export workflows.
  • Added PageRivet.YamlWeb for rendering *.page.yml and *.page.yaml pages using the pagerivet.page/v1 schema.
  • A single NativeWebView can now switch between HTML and PageRivet YAML previews.
  • YAML pages can use project CSS, JavaScript, MJS, managed resources, and declarative events.
  • Added packaging scripts and guidance for Windows x64 Portable, macOS .app, and Linux x64 Portable builds.

Changed

  • Reorganized the workspace into three independently titled columns—Preview, Editor, and Project—with Sources and Resources inside the Project panel.
  • Editable managed resources now open in the existing code editor; drafts stay in memory until apply and pass validation and atomic saving.
  • Preview and export now share the same YAML renderer, and exports include both the original YAML and generated HTML.
  • Separated project workflows, preview, and Avalonia UI into PageRivet.Application, PageRivet.Preview, and PageRivet.Avalonia.
  • Unified settings, MCP authentication, Recovery, WebView, and Bridge data paths through platform services and moved MCP approval evaluation into the shared application layer.

Removed

  • Removed the Windows Forms UI and direct Scintilla5.NET and Microsoft.Web.WebView2 dependencies from the active product.
  • Removed the old WinForms sources, tests, and legacy solution after completing the migration.
  • Removed tracked 2.3.2 and 2.3.3 binaries and older publish artifacts.

Stability and Security

  • Ordinary YAML is never executed; only PageRivet YAML pages matching both the filename rules and pagerivet.page/v1 schema are processed.
  • Applied limits for YAML size, nodes, depth, aliases, fields, paths, and events.
  • Preserved checks for relative paths, reparse points, loopback, external navigation, MCP scope, and revisions.
  • Settings, recent projects, MCP authentication and instance data, and Recovery data remain excluded from packages.

Validation and Release Candidate

  • The Release build completed with 0 warnings and 0 errors.
  • All 384 tests passed: 330 common, 44 Avalonia, and 10 Windows tests.
  • Passed six repeated HTML/YAML switches in Windows NativeWebView and the portable smoke test.
  • The self-contained Windows x64 Portable package contains 403 files totaling 274,274,741 bytes; the ZIP is 99,711,015 bytes.
  • ZIP SHA-256: 01CE6EE9D69E849B749D71795B7E4358F85C3F37A6429FFA36E4C4630253EA58
  • Confirmed zero forbidden WinForms, WebView2, or Scintilla dependencies and zero personal-data findings.

Remaining Validation

  • Real-environment NativeWebView and Bridge validation remains for macOS and Linux.
  • Further validation is planned for Korean IME, high-DPI and accessibility behavior, and long-term stability.
  • macOS signing and notarization and clean-environment package validation on each platform remain pending.

PageRivet 2.3.3

허용된 MCP 상태 변경 작업에 현재 승인 정책을 일관되게 적용하고, 외부 리소스 가져오기와 프로젝트 내보내기의 별도 강제 승인 예외를 제거했습니다.

변경 사항

  • ‘항상 확인’은 검증을 통과한 허용 작업도 적용 전에 사용자 확인을 요구합니다.

PageRivet 2.3.0

2026.08.26 · Portable

PageRivet 2.3.0 adds automatic Claude Desktop connection support.

Added

  • Added PageRivet.StdioBridge for Claude Desktop.
  • Detects both the standard installer and the Microsoft Store/MSIX build of Claude Desktop, and can automatically apply the connection configuration from the MCP settings screen.
  • Registers a single fixed pagerivet Bridge entry in the Claude Desktop configuration.
  • Added per-process connection registration information so the Bridge can locate the local MCP address of a running PageRivet instance.
  • Added single-connection ownership so a Claude Desktop connection is assigned to only one PageRivet instance at a time.
  • If PageRivet exits, the Bridge keeps the Claude Desktop connection and the last confirmed tool definitions, then reconnects once PageRivet runs again.
  • When Claude Desktop is detected, a separate notice window after startup explains the single-connection limit.
  • The Claude Desktop entry in the MCP settings screen shows the same single-connection notice.
  • Added text preview and editing for JSON, XML, CSV, WebVTT, TXT, Markdown, Web App Manifest, Source Map, glTF JSON, and SVG resources.
  • Added a dropdown to sort the resource list by name, extension, kind, or size in ascending or descending order.
  • Added the read_text_resource, create_text_resource, and apply_text_resource_patch MCP tools for managed resources.

Changed

  • Included Claude Desktop in the list of clients with automatic connection support.
  • Configured the Claude Desktop entry to record only the Bridge executable path, without writing the MCP Access Token or project information directly.
  • Aligned the product, assembly, and file versions to 2.3.0 / 2.3.0.0.
  • Included the PageRivet.StdioBridge executable and required runtime files in the portable package.
  • Reduced the main window’s initial size from 1400×900 to 1120×720, about 20% smaller. Minimum size, user resizing, and maximize behavior remain unchanged.
  • Expanded the built-in MCP tool set from 39 to 42 commands.

Fixed

  • Fixed nullable MCP response fields to serialize as an explicit null instead of being omitted when no value is present.
  • This fix resolved a compatibility issue in Claude Desktop where tool calls such as get_project_info failed because the structured content response’s actual fields diverged from the output schema.
  • If only the Bridge executable exists while required DLLs or runtime configuration files are missing, PageRivet now reports a configuration error instead of showing a successful connection.
  • When a leftover 5-slot trial configuration remains, only entries confirmed as PageRivet-created, pagerivet-2 through pagerivet-5, are now cleaned up.

Security

  • Creates a claude_desktop_config.json.pagerivet.bak backup before changing the Claude Desktop configuration.
  • Preserves MCP server entries that differ from the existing Claude Desktop configuration.
  • If multiple genuine Claude Desktop configuration files are found at once, none is arbitrarily selected or modified.
  • MCP entries with the same name that are in use by another program or changed by the user are not removed unless PageRivet ownership is confirmed.
  • Runtime registration records only the InstanceId, PID, process start time, connection name, and loopback address; the MCP Access Token and project information are never recorded.
  • Even if a PID is reused, PageRivet is not recognized as valid unless the process start time also matches.
  • A Claude Desktop connection can only be returned by an owner whose LeaseId also matches, so a previous process cannot remove a new connection.
  • The connection between the Bridge and PageRivet uses only the local loopback address and keeps the existing Bearer authentication.
  • In-progress tool requests are not automatically resent to another PageRivet instance if the connection target changes or is temporarily lost.

Claude Desktop Support Scope

  • Due to its connection model, Claude Desktop can connect to only one PageRivet instance at a time.
  • Multiple PageRivet connections from existing Streamable HTTP clients such as Codex and Claude Code remain unaffected.
  • After the initial connection setup or a Bridge path change, Claude Desktop must be fully closed and relaunched.
  • Once Claude Desktop has confirmed the Bridge’s tool list, simply closing and relaunching PageRivet is enough for the Bridge to find and reconnect to the new PageRivet instance.
  • Automatic termination or forced restart of the Claude Desktop process, and automatic resending of in-progress tool requests, are not supported.

  • MCP 리소스 작업 후 에디터의 리소스 목록과 미리보기가 즉시 갱신되도록 했습니다.
  • 코드 및 진단 탭을 더블 버퍼링 방식으로 그려 탭 전환과 코드 입력 중 발생하던 흰색 깜빡임을 줄였습니다.
  • 기록과 MCP 로그의 열 뒤에 남던 흰색 네이티브 헤더 영역을 제거했습니다.
  • WinForms 테두리와 불완전한 라운드 클리핑을 제거하고 색상 톤만으로 작업 영역을 구분하도록 수정했습니다.

보안

  • 프로젝트 상대 경로가 프로젝트 루트 밖으로 벗어나지 못하도록 경로 정규화와 Windows 예약 이름 검사를 적용했습니다.
  • 관리 리소스 디렉터리의 심볼릭 링크와 재분석 지점 사용을 차단했습니다.
  • MCP 리소스 요청 적용 전에 프로젝트 Revision, 현재 리소스 목록과 가져오기 원본 상태를 다시 확인합니다.
  • 외부 리소스 원본 경로와 MCP 인증 정보를 도구 응답 및 포터블 배포본에 포함하지 않습니다.

Expanded application state inspection and safe action requests while strengthening security boundaries around user-controlled operations.

Added

  • get_ui_state: Inspect the current language, theme, and major UI processing state.
  • get_preview_state: Inspect Preview initialization and the currently displayed page.
  • get_recovery_status: Inspect safe Recovery metadata without exposing source content.
  • get_mcp_status: Inspect MCP server, connection, and approval state without credentials.
  • get_mcp_log: Read recent MCP activity logs with sensitive values removed.
  • get_export_presets: Read built-in and user export preset lists.
  • save_project: Save only the validated current project without applying pending edits.
  • refresh_preview: Refresh the current Preview without changing the project.
  • preview_html_page: Display an existing project HTML page in Preview.
  • export_project: Request export using a preset or non-persistent one-time settings.

Changed

  • Expanded the built-in MCP tool set from 47 to 56.
  • Added a broker that routes MCP application requests through the UI thread and existing coordinators.
  • Clarified preset persistence, one-time settings, and final approval requirements for exports.
  • Final export approval now shows project, format, destination, overwrite, and warning details in Korean and English.
  • Updated the built-in MCP guide and README for 56 tools and the expanded application access scope.
  • Unified product, assembly, and file versions as 2.3.2 / 2.3.2.0.

Stability & Security

  • Restricted AI from Undo, Redo, History restoration, Recovery apply/delete, security and approval changes, project switching, and app lifecycle actions.
  • Removed the disallowed restore_history MCP tool and related AI restoration paths.
  • MCP saving requires matching active project and revision and rejects pending editor buffers.
  • Preview actions are limited to existing HTML pages in the active project.
  • Recovery status returns only safe metadata, never source content or absolute paths.
  • MCP status and logs never return access tokens and redact sensitive values.
  • MCP export always requires final user approval.
  • Rejected exports create no output or export settings.
  • One-time export settings are not persisted to user presets or the current selection.

PageRivet 2.3.2

· Portable ZIP

애플리케이션 상태 조회와 안전한 작업 요청 범위를 확장하고, 민감한 사용자 제어 영역의 보안 경계를 강화했습니다.

추가

  • get_ui_state: 현재 언어, 테마와 주요 UI 처리 상태를 조회합니다.
  • get_preview_state: Preview 초기화 여부와 현재 표시 페이지를 조회합니다.
  • get_recovery_status: 소스 내용을 노출하지 않고 Recovery 존재 여부와 복구 가능 메타데이터를 조회합니다.
  • get_mcp_status: 인증값을 제외한 MCP 서버, 연결 및 승인 정책 상태를 조회합니다.
  • get_mcp_log: 민감정보가 제거된 최근 MCP 활동 로그를 조회합니다.
  • get_export_presets: 기본 및 사용자 내보내기 프리셋 목록을 읽기 전용으로 조회합니다.
  • save_project: 미적용 편집을 자동 적용하지 않고 검증된 현재 프로젝트 상태만 저장합니다.
  • refresh_preview: 프로젝트를 변경하지 않고 현재 Preview를 새로고침합니다.
  • preview_html_page: 현재 프로젝트에 존재하는 HTML 페이지를 Preview에 표시합니다.
  • export_project: 기존 프리셋 또는 비영속 일회성 설정으로 프로젝트 내보내기를 요청합니다.

변경

  • 내장 MCP Tool 수를 47개에서 56개로 확장했습니다.
  • MCP 애플리케이션 요청을 UI 스레드와 기존 Coordinator로 전달하는 전용 브로커를 추가했습니다.
  • 내보내기 요청에 프리셋 선택 영속화 여부, 일회성 설정 여부와 최종 승인 요구를 명시했습니다.
  • 한국어·영어 최종 내보내기 승인 안내에 프로젝트, 형식, 출력 위치, 덮어쓰기 및 경고 정보를 표시합니다.
  • 내장 MCP 가이드와 기본 README를 56개 Tool 및 애플리케이션 접근 범위에 맞게 갱신했습니다.
  • 제품, 어셈블리 및 파일 버전을 2.3.2 / 2.3.2.0으로 통일했습니다.

안정성 및 보안

  • AI가 Undo, Redo, History 복원, Recovery 적용·삭제, 보안·승인 설정 변경, 프로젝트 전환 및 프로그램 종료·재실행을 수행하지 못하도록 제한했습니다.
  • 정책상 허용되지 않는 restore_history MCP Tool과 관련 AI 복원 경로를 제거했습니다.
  • MCP 저장은 현재 활성 프로젝트와 Revision이 일치할 때만 실행하며 미적용 편집 버퍼가 있으면 거부합니다.
  • Preview 작업은 현재 활성 프로젝트에 이미 존재하는 HTML 페이지만 대상으로 합니다.
  • Recovery 상태는 파일명과 저장 시각 등 안전한 메타데이터만 제공하고 소스 내용과 절대 경로를 반환하지 않습니다.
  • MCP 상태와 로그는 Access Token을 반환하지 않으며 민감값을 제거합니다.
  • MCP 내보내기는 자동 적용 승인 정책에서도 항상 사용자 최종 승인을 요구합니다.
  • 사용자가 거부한 내보내기는 출력이나 내보내기 설정을 만들지 않습니다.
  • 일회성 내보내기 설정은 사용자 프리셋과 현재 선택 설정에 저장되지 않습니다.
